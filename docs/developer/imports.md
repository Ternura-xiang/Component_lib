# 导入与资料匹配模块

这组模块有不同的输入与安全边界，不要混为一个自动抓取流程。

## 1. BOM：`bom.py`

`parse_bom()` 解析 CSV/XLSX 并映射中英文表头；`preview_bom()` 在现有元件中生成候选，编号精确匹配优先于名称模糊匹配。预览不得直接扣库存；用户确认后由 `Database.commit_bom()` 原子出库。

新增列名或格式时同步更新 `tests/test_bom.py`，特别验证重名、歧义、缺数量和错误文件格式。

## 2. 离线订单：`order_import.py`

`parse_saved_orders()` 从用户保存的 ZIP/HTML/MHTML 静态内容提取商品。它不会执行页面脚本；订单数据经 `preview_order_import()` 标注创建/匹配/跳过，再由 `import_order_lines()` 在事务中入库。通过订单号与立创编号形成重复导入约束。

修改解析器需覆盖页面结构变化、编码、安全输入、相同行去重与事务失败等场景，见 `tests/test_order_import.py`。

## 3. 立创当前商品页：`jlc_product.py` + `ui/jlc_browser.py`

匿名临时内嵌浏览器由**用户亲自搜索并选中当前商品详情页**；搜索结果可能使用新窗口打开，`SafeJlcPage.createWindow()` 将它重定向到当前视图。解析器只接收当前已渲染 HTML，优先抽取 JSON-LD 与“商品参数”区，必须排除并列的替代料和推荐商品区。

`JlcMergeDialog` 将商城有值的基础字段和参数默认全选；用户可逐项取消。“应用到入库表单”只修改 UI 草稿，不得在合并对话框中写数据库。不要扩展为自动枚举商品、私有 API、账号登录或后台爬取；浏览器应维持临时会话和关闭清理行为。

`jlc_import.py` 包含相关基础导入辅助，变更时检查其现有调用关系和单元测试。

## 4. 其他公开 HTTPS 产品页：`web_sources.py`

`PublicWebEnricher` 只在用户主动提供页面后预览单页元数据。其访问边界包括 HTTPS、禁止私有/本机网络目标、robots 检查、域名限速与缓存、403/429 暂停，以及页面大小约束。不得通过代理轮换、登录模拟或验证码绕过规避网站限制。

## 推荐的新增来源流程

先确定输入方式与站点政策，再实现**纯解析函数**（输入静态 HTML/文本，输出草稿），添加离线 fixture 与单测，然后接入预览界面或已有服务。若涉及网络访问，额外补网络安全与错误处理测试。保证**解析/预览和库存提交完全分离**。
