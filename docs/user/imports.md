# 商城资料与订单导入

程序提供两种**不同用途**的商城相关工作流：为单个元件补资料，以及从保存的订单文件批量入库。

## 单个商品资料：辅助填写

在 **入库** 页面可打开立创商城的临时内嵌浏览器，由用户自行检索并明确确认**当前商品详情页**。程序解析当前页面已有的产品基本资料和“商品参数”表格，不把并列的“替代料”或“买了又买”作为参数。剪贴板导入作为备用路径。

确认窗口会显示现有值、商城值和最终值。商城资料默认**全部勾选**，包括封装、品牌、类别及所有商品参数；如果不希望覆盖某个现有值，必须在确认前取消该行对号。折叠元件详情不会取消隐藏字段，点击“确认资料”只更新草稿，最后仍需点击“确认入库”。

该方式不是自动批量爬取商城，也不需要在程序中登录商城。内嵌浏览器使用不持久化的临时会话，关闭时清理 Cookie 和内存缓存；不会下载页面文件。网页资料可能缺失或发生变化，尤其应确认型号、封装和单位。

## 导入已保存的立创订单

1. 在浏览器中将相关订单页面保存为程序支持的 **ZIP / HTML / MHTML** 文件。
2. 进入左侧 **入库**，从其订单导入入口选择本地文件。
3. 解析时右侧显示当前订单日期、元件和已解析数量。每批固定最多导入 1000 条；超过时先完成本批，再重新选择同一文件继续未导入商品。
4. 等待离线解析后，在预览表中检查元件名称、型号、数量、类别、品牌、商品链接和各行仓库。若保存页面仍显示“查看全部商品”，网页尚未请求的额外商品不会存在于静态文件中；程序会立即提示，应回到网页展开后重新保存。
5. 未导入行默认勾选；已经导入的相同行自动取消并禁用。取消不需要的行，必要时双击修改单元格，或通过右键菜单打开完整编辑。
6. 检查新增/匹配状态，点击“确认勾选项入库”并在二次确认中同意；导入结果再到 **元件库存** 与 **库存流水** 核对。解析、预览和资料匹配本身不会写库存。

同一订单号与立创编号组成的重复导入键用于避免重复入库。已经入库的相同行不应反复导入。选中行在单个数据库事务内提交；发生错误则整体回滚。订单号和购买日期会保存并在元件库存中显示。订单号不会显示在普通入库表单；手工选择已有元件时，购买日期保持为空，不会自动沿用历史日期。

## 隐私与边界

订单解析处理本地保存的静态页面，不执行页面脚本，不会保存联系人、收货和物流详情。公开网页元数据读取功能有额外访问限制；**不要用它批量抓取或绕过站点访问政策**。

若列表中某行匹配了错误的已有元件，请在提交前更正；导入后的改动会产生真实库存流水，无法只靠重新预览撤回。
